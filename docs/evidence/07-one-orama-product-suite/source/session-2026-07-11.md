## 2. Stage 2 — symbiosis v0, operator → Zetta (landed)

The **operator → Zetta** direction is done and AKS-validated — "Zetta is the operator's datastore" is
real, not just designed:

- **Operator provisions its OWN schema onto a Zetta node** ([operator `c268508`](https://github.com/oramasearch/orama-cloud-v1-operator/commit/c268508)):
  an in-cluster Job issues idempotent DDL to `/v1/sql` — `orama_control` (`components`,
  `reconcile_events`) + `orama_data` (`documents`). Gated by `spec.provisionOperatorSchema` (default
  true). Zetta SQL has no `IF NOT EXISTS`, so statements apply individually and "already exists" is
  tolerated.
- **Operator continuously syncs observed state into Zetta** ([operator `9301093`](https://github.com/oramasearch/orama-cloud-v1-operator/commit/9301093)):
  coarse component-granular CR statuses mirror into `orama_control.components` **on change only**
  (anti-flap; 60 s requeue), each row **namespaced per operator** (`ORAMA_OPERATOR_ID`) so many
  operators can share one Zetta cluster. Validated: **24 component rows** synced.
- **Chart RBAC fix** ([operator `dac80e6`](https://github.com/oramasearch/orama-cloud-v1-operator/commit/dac80e6)):
  leader-election Role + the full `orama.cloud` manager ClusterRole so the in-cluster ServiceAccount
  can actually reconcile all CRDs.

**Caveats:** the node **drops ~2/3 of back-to-back requests** ([zetta#731](https://github.com/oramasearch/zetta/issues/731))
so the Job retries hard; the pod **readiness probe is disabled** ([operator#68](https://github.com/oramasearch/orama-cloud-v1-operator/issues/68))
to stop a flaky HTTP server flapping the pod out of its Service.

**Remaining for Stage 2:** the **Zetta → operator** intent/read loop + e2e coverage
([operator#100](https://github.com/oramasearch/orama-cloud-v1-operator/issues/100)).

## 3. Governance / auth — the full story (built, merged, then a hardening backlog)

**Wave 1 — built + merged.** The comprehensive authn/authz epic
[zetta#743](https://github.com/oramasearch/zetta/issues/743) (users → roles → scoped grants → RLS →
hashed tokens → default-deny gate) shipped as PRs [#752](https://github.com/oramasearch/zetta/pull/752) /
[#754](https://github.com/oramasearch/zetta/pull/754) / [#755](https://github.com/oramasearch/zetta/pull/755) /
[#756](https://github.com/oramasearch/zetta/pull/756) / [#757](https://github.com/oramasearch/zetta/pull/757),
now on `main`. (Design detail in the [2026-07-10 log §6](session-2026-07-10.md).)

**Peer security hardened** — [operator#94](https://github.com/oramasearch/orama-cloud-v1-operator/pull/94):
the operator seeds **one shared cluster join token** and makes **peer traffic mTLS-only**.

**Wave 2 — the hardening backlog (⚠️ ALL OPEN).** A security review of the shipped auth system found
**11 exploitable gaps** — this is the gate before the governance/Enterprise story is production-safe:

| # | Gap |
|---|---|
| [zetta#759](https://github.com/oramasearch/zetta/issues/759) | Privileged SQL statements skip the permission check — a read-only user can mint an owner token / drop tables |
| [#760](https://github.com/oramasearch/zetta/issues/760) | Column masking bypassable via aggregate (`SELECT id, MAX(salary) … GROUP BY id` leaks hidden values) |
| [#761](https://github.com/oramasearch/zetta/issues/761) | Role-management permission unbounded — a holder can self-grant admin; built-in roles editable/deletable |
| [#762](https://github.com/oramasearch/zetta/issues/762) | Auth **off by default** — a network-facing node accepts unauthenticated requests; masking/row-security no-op for legacy tokens |
| [#763](https://github.com/oramasearch/zetta/issues/763) | A node joining a cluster can create a **second owner** that replicates cluster-wide |
| [#764](https://github.com/oramasearch/zetta/issues/764) | Replicated identity records trusted with **no proof of origin** — any peer can inject an owner token |
| [#765](https://github.com/oramasearch/zetta/issues/765) | RLS policy with no condition treated as **allow-all instead of deny** (fail-open) |
| [#766](https://github.com/oramasearch/zetta/issues/766) | Any authenticated user can list every tool + read the full policy/user/role catalog |
| [#767](https://github.com/oramasearch/zetta/issues/767) | Blob permissions match by **text prefix**, not path boundary (`report` also grants `report-secret`) |
| [#768](https://github.com/oramasearch/zetta/issues/768) | Orchestration tools ungrantable once auth is enforced — even admin loses deploy/run |
| [#769](https://github.com/oramasearch/zetta/issues/769) | Hardening: hash the admin token, constant-time compare the legacy secret, audit SQL mutations |

Plus adjacent hardening: [#770](https://github.com/oramasearch/zetta/issues/770) (join-token env
exposure), [#771](https://github.com/oramasearch/zetta/issues/771) (routing-table address
validation / DoS + log-injection), [#772](https://github.com/oramasearch/zetta/issues/772)
(listen-port follow-ups), and the older mTLS V2 items
[#669](https://github.com/oramasearch/zetta/issues/669) (CSR enrollment, peer-cert pinning,
revocation) / [#670](https://github.com/oramasearch/zetta/issues/670) (join token through burst
provisioners).

## 7. Connect surface + tooling

- **Connecting guide** — [operator#102](https://github.com/oramasearch/orama-cloud-v1-operator/pull/102)
  (merged): `docs/connecting.md` for `OramaZettaCluster` — client-port **addressing** (in-cluster DNS /
  `port-forward` / Ingress), the four **surfaces** (REST+SQL `/v1/*`, MCP `/mcp`, self-describing
  `mcp.md` + `llms.txt`, web portal), and the **auth model**: peer traffic is always mTLS via a shared
  join token (`<name>-zetta-cluster`); the client surface needs `Authorization: Bearer <token>` from the
  **MCP-token** Secret (`<name>-zetta-mcp`) or, under `spec.requireAuth` / `--require-auth`, the
  **admin-token** Secret (`<name>-zetta-admin`) — unauthenticated (trusted-network only) if neither.
  Referenced from the `one-orama-dev` skill. **Caveat:** it predates the §3 hardening backlog —
  `--require-auth` is *necessary but not yet sufficient* for hostile/public exposure until
  [#759–#769](https://github.com/oramasearch/zetta/issues/762) land (e.g. #762 auth-off-by-default,
  #759 privilege-check bypass).
