## 1. The multi-cloud cluster (proven)

Stood up **one Zetta cluster** across:

| Node | Where | Role |
|---|---|---|
| node-0, node-1 | home **k0s** (server2), one `OramaZettaCluster` CR, `replicas: 2` packed on the host | operator-managed |
| macOS GUI node | the laptop, headed SDL3/ImGui (not `--headless`) | dial-out |
| AKS node | **Azure eastus** | wan-accessible rendezvous |

Verified **bidirectional cross-cloud CRDT replication**: a row written on the AKS node in Azure converged
to the two home k8s nodes and the laptop in ~5 s. "Zetta is the mesh" demonstrated at cloud scale.

**Operator capabilities built for this** (shipped to `orama-cloud-v1-operator` `main`):
- `spec.clusterName` / `spec.externalPeers` / `spec.hostNetwork` / `spec.exposePeerLoadBalancer` — the
  cross-cluster "sibling / slice" fields.
- **hostNetwork ordinal port-packing** — `replicas>1` on one host binds `7777+n`/`4800+n`; ordinal from
  `POD_NAME` (not `$HOSTNAME`, which is the node under hostNetwork); container ports + peer-port probes
  dropped under hostNetwork.
- **`WATCH_NAMESPACE`** — run the operator locally scoped to one namespace so it never disturbs
  production CRs (used to bring up the AKS slice without touching `zetta.oramadev.net`'s node).
- **host-IP peer seed** — hostNetwork packed peers seed off `status.hostIP`, not `127.0.0.1` (see §3).

## 2. The node-reachability model (architecture correction)

A wrong turn (provisioning an inbound Azure LoadBalancer — and source-locking it to a home IP — to
"reach" the AKS node) was corrected into the right model:

- A node is **wan-accessible** (a routable address; a rendezvous others dial **out** to), **ephemeral**
  (burst/autoscaled, expected to churn), or **dial-out-only** (behind NAT / a private VNet — outbound
  only, **no inbound**).
- The mesh **self-forms**: put a wan-accessible address in the nodes table; private nodes dial out; Zetta
  relays + computes the route table. A home/AKS-pod node is **always the initiator**.
- **Anti-pattern (now documented everywhere):** never put an inbound LoadBalancer on a private node.

Documented in Zetta `docs/cluster/cluster.md`, operator `docs/zetta-datastore.md`, and the
`one-orama-dev` skill (v1.5.0). The routing-table engine work is [zetta#739](https://github.com/oramasearch/zetta/issues/739);
the operator's node-type fields are [operator#74](https://github.com/oramasearch/orama-cloud-v1-operator/issues/74).

## 3. Bugs found + diagnosed (from pushing the mesh across clouds)

| Symptom | Root cause | Outcome |
|---|---|---|
| **100 % CPU** on the two home nodes | boost.corosio **epoll reactor busy-spins** on a persistently-errored peer fd (`EPOLLHUP`/`ERR` re-fires, never reaped) — Linux-only; kqueue fine | [zetta#740](https://github.com/oramasearch/zetta/issues/740) |
| **~30 % CPU + 460 leaked connections** | **peer identity keyed on one address** — a `127.0.0.1`/LB-VIP seed never matches the peer's advertised address, so `reconnect_loop` redials forever | [zetta#739](https://github.com/oramasearch/zetta/issues/739) |
| membership **flapping** (a node in/out) | same as above — the AKS node advertised its unreachable pod IP | [zetta#739](https://github.com/oramasearch/zetta/issues/739) |
| **port drift** (`:7777`→`:7779`) after restart | no `SO_REUSEADDR` → can't rebind while old sockets are in `TIME_WAIT` | [zetta#738](https://github.com/oramasearch/zetta/issues/738) |

Diagnosed with `gdb`/`sample`/`ss` down to the reactor thread and the TIME_WAIT sockets. The operator-side
**host-IP seed fix** (dial the address the peer advertises) shipped immediately and dropped the live cluster
from 30 % → ~7 % CPU, confirming the leak diagnosis.

## 6. Comprehensive authn/authz for Zetta (designed + built)

Built **on** Zetta's existing governance engine (Principals / AccessKeys / Scope / Capabilities /
deny-by-default `authorize()` / audit / CRDT replication / mTLS peering), not from scratch:

- **users** ← **roles** (groupings of **permissions**; built-in `admin`/`writer`/`reader` + custom) ←
  **scoped grants** (permission + object scope: global / db / table / `db.table(cols)` / blob / **MCP tool**).
- **row-level security** — `system.policies` with `USING`/`WITH CHECK` predicates, evaluated by the
  existing `WHERE` engine with `current_user()`/`current_roles()`.
- **tokens** — API tokens + access tokens (pre-assigned long password), **hashed** at rest
  (SHA-256+salt, constant-time compare), authenticating **as a user**.
- **one default-deny gate** — `bearer → user → roles → capabilities` on every HTTP/MCP/REST path
  (`--require-auth`); MCP `tools/call` per-tool + `tools/list` filtered; peering stays on mTLS.
- **bootstrap owner** — an `admin` user + access token seeded on first run (`--admin-token`) so the
  system is never locked out.

Epic [zetta#743](https://github.com/oramasearch/zetta/issues/743) — **closed**, all five subs delivered.
